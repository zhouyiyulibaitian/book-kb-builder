# 阅读总结文档模板（txt）

总结文档是**这本书在知识库里的唯一出口**：以后要了解这本书、要在写作或研究里引用它，
靠的就是这份 txt。所以它的第一要务不是"写得好"，而是**每一句话都能回到原书的具体页面**。

文件落盘位置：`知识库/<类别>/<图书名称>/<图书名称>_阅读总结.txt`（UTF-8，纯文本）。
文件名必须和书名目录一致，`kbtool.py` 靠 `_阅读总结.txt` 后缀识别书目。

## 三种出处标记（全文统一，不许混用）

| 标记 | 含义 | 使用条件 |
|---|---|---|
| `(p.123)` | 来自原书 **PDF 第 123 页**的**文字** | 该书有可用文字层，你在提取文本里读到 |
| `(p.123·图)` | 来自原书 **PDF 第 123 页**的**图像** | 扫描版或图版页，你看了渲染出来的页图 |
| `【联网补充】` | 来自**联网检索**，不是原书内容 | 只能出现在第八节，且必须带来源与可信度 |

页锚一律用 **PDF 页号**，不用书上印的页码：前者无歧义、可直接跳转、可被脚本校验范围。
印刷页码在章节地图里附注即可（`第一章（PDF p.40 / 印刷 p.1）`），
并在书目信息里写明换算关系，例如：

```
页锚说明：本文 (p.N·图) 中的 N 一律是 PDF 页号（不是书上印的页码）。
  经校准，正文印刷页码 + 39 = PDF 页号（印刷 p.1 = PDF p.40，印刷 p.354 = PDF p.393）。
  前置页用罗马数字，未纳入此换算。
```

一条硬规矩：**正文各节只允许出现前两种标记**。凡是联网来的东西，一律只能放在第八节。
这条会被 `verify.py` 机器检查（正文里出现网址即判不通过）。

## 必须遵守的写作纪律

1. **无出处不落笔。** 每个实质性判断后面都要有页锚。写不出页锚，就说明它不在原书里。
2. **引文必须逐字。** 用「」包起来的内容必须和原书一字不差。要省略中间部分用 `……`，
   脚本会分段核对省略号两边的片段。`verify.py` 会回原文逐字比对，编造的引文会被抓出来。
3. **不替作者补全。** 原书没讲的，宁可写「本书未涉及……」也不要补。设计类书籍尤其容易
   被"常识补全"污染——比如书里讲了网格但没讲黄金比，就不要顺手把黄金比写进总结。
4. **区分"书中观点"与"你的归纳"。** 前者是「作者认为……」+页锚；后者写明「（本节为归纳）」
   并保证归纳不引入原书没有的信息。
5. **元数据引用标 `(元数据)`。** 书名、作者、出版社来自 PDF/EPUB 元数据而非正文，
   这类内容不要用「」引号，写成 `（元数据）`，脚本会跳过核对。
6. **老老实实写覆盖度。** 读了多少写多少。覆盖度低不是错误，假称读全了才是。

## 关于篇幅

不要为了"看起来完整"而稀释。一本 800 页的书，一份 2000-4000 字、页锚扎实的总结，
比一份 10000 字却没有出处的总结有用得多。页锚密度是个好指标：大致每 100 字
至少有一个页锚，说明它确实长在原书上。
